# v0.1.0: the formula engine

Measured on 2026-11-06 on the release commit with Go 1.26.5, linux/amd64,
on an Intel Core Ultra 9 275HX with 24 threads and 31 GB available to the
Linux VM (WSL2, kernel 6.18). The benchmarks ran ten times on an idle
machine and are reported by benchstat as the mean with its spread. The
budgets are those of [ADR-0012](../adr/0012-performance-gates.md).

## The VM against its budgets

| Measure | Budget | Result |
|---|---|---|
| Five-operation arithmetic formula on the Go VM, `a * b + c / d - e` | < 100 ns, 0 allocations | 13.7 ns ± 1%, 0 allocations |
| Core binary, `fadodb` with the engine, static build | ≤ 15 MB | 2.9 MB |

The other budgets of ADR-0012 need the store, the statechart, the server
or the browser VM, which later phases bring; they stay targets until then.

## Compiler and VM

On the formula `IF(qty > 0 AND NOT ISBLANK(price), ROUND(qty * price * (1 - discount%), 2), 0)`
unless noted.

| Benchmark | What | ns/op | B/op | allocs/op |
|---|---|---|---|---|
| Lex | tokens | 1,058 ± 4% | 2,152 | 7 |
| Parse | syntax tree | 2,246 ± 1% | 2,976 | 32 |
| Bind | typed bytecode | 3,575 ± 3% | 5,200 | 69 |
| VM_Arithmetic5 | `a * b + c / d - e` | 13.7 ± 1% | 0 | 0 |
| VM_IfRoundCompare | the formula above | 35.4 ± 1% | 0 | 0 |
| VM_Text | `UPPER(LEFT(name, 3)) & "-" & TEXT(n)` | 111.1 ± 2% | 32 | 5 |

Compiling is a definition-time cost, paid once per formula; the VM runs
the compiled program. The text benchmark's allocations are the result
texts themselves.

## The three evaluators

The conformance suite holds 747 evaluation cases in 10 suites, 135
accepted and 87 rejected syntax cases, and 67 accepted and 68 rejected
binding cases. Every evaluation case passes exactly on the Go VM, on
SQLite through modernc.org/sqlite and on DuckDB through the `analytics/`
module.

The property campaigns generate random, well-typed formulas with inputs
and context and run each on the VM and on a SQL target, at a text limit of
1,024 code points ([ADR-0021](../adr/0021-size-limits.md)). The acceptance
runs of this release:

| Target | Formulas | Divergences | Time | Throughput |
|---|---|---|---|---|
| SQLite, 8 workers | 1,000,000 | 0 | 67 s | 14,900 formulas/s |
| DuckDB, 12 workers | 1,000,000 | 0 | 23 min, sharing the cores with the gates | 1,400 formulas/s idle, 8 workers |

Of each million, 209,914 formulas end in an error code on the VM, and the
SQL target must end in the same code. The DuckDB throughput is from an
idle run of 50,000 formulas in 36 s; the acceptance run itself overlapped
with the quality gates. The throughput is that of the whole
loop, generating, binding, running on the VM and on the engine through
database/sql; the DuckDB figure is one statement per formula on an
in-memory database per worker, not the set-wise path of Phase 8.

## Reproduce

```
go test -run '^$' -bench . -benchmem -count 10 ./internal/formula/
FADODB_FUZZ_N=1000000 go test -run TestProperty -v ./internal/formula/sqlitefn/
cd analytics && FADODB_FUZZ_N=1000000 go test -run TestProperty -v ./...
```
